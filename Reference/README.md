# Reference

Source material for the game Impact Theory is modeled on. Read-only. Nothing here is a
specification and nothing here is licensed for reuse.

## Files

| File | What it is |
|---|---|
| `reference-clip.mp4` | The reference gameplay clip, 4.6 seconds, re-encoded to H.264 at 540 px wide so it plays anywhere. 546 KB. |
| `reference-clip-original.MOV` | The original phone screen recording. HEVC, 1320 x 2868, 60 fps, 10.5 MB. Kept because the re-encode loses detail. Many tools cannot decode it. |
| `frames/frame_01.jpg` to `frame_09.jpg` | Nine stills pulled from the clip at 2 fps, 660 px wide. |

## Use the frames, not the video

The build brief for this project was written from these nine frames, not from the video. Most
coding agents cannot decode video but can read images, so the frames are the reliable path. The
video is here for a human, and for the pacing questions a still cannot answer: how fast the
collapse reads, how quickly shots follow each other, how much of the screen the cannon takes.

## What the clip is not

It is another studio's commercial game. It describes the target; it does not license its
vocabulary. Do not copy its name, art, sounds, icons, UI text or level layouts into this project.
Rule 9 of the governing standards, original identity only.

## Two things the frames could not settle

Both are marked UNVERIFIED in the build brief and both need a human to answer them.

1. **Fire mode.** Several balls are in flight at once. Whether one tap fires one ball, a burst, or
   a held stream is not visible. Resolving question: does one tap produce one ball or a burst?
2. **The HUD.** No score, ball counter, level number or button appears in any of the nine frames.
   Whether the real game hides its HUD for promotional footage, or has none, is unknown. Resolving
   question: does gameplay show a score and an ammo count?
